# r9.1 (v2.5.1 / versionCode 16) — fixes on top of r9 (v2.5.0 / 15)

Static review + targeted fixes. Nothing new was built as a feature; every change
below repairs something that was broken or unreliable in r9.

## Fixed

### Build blockers
1. **31 broken relative imports in 10 Dart files** (`flutter build` could not
   compile). `shared/mld_widgets.dart` used `../../core/...` (should be
   `../core/...`); the nine r9 screens (monk, community, lock, tasks, prime,
   account, safety, emergency_codes, companion) used `../../../` (should be
   `../../`). `mld_widgets.dart` is imported by nearly every screen, so this
   broke the whole app.

### Enforcement / detection
2. **BACK-key consumption was dead code.** `FLAG_REQUEST_FILTER_KEY_EVENTS`
   set from code is ignored unless the service XML declares
   `android:canRequestFilterKeyEvents="true"`. Added it (and the flag) to
   `accessibility_service_config.xml`. `onKeyEvent` now also consumes both the
   DOWN and UP halves of BACK / APP_SWITCH while the wall is showing.
3. **In-session shorts detection used the legacy text-hint `ShortsDetector`**
   (generic labels such as "Subscriptions", "Following", "Your story";
   traversal depth 3). It could fire on normal browsing — each hit counts
   toward the 30-minute Cage — and miss real feeds. The in-session ladder now
   uses the same view-id based `ReelsDetector` as the out-of-session path.
   `ShortsDetector.kt` is left in the tree but is no longer referenced.
4. **Facebook Lite:** `video_view` also backs ordinary inline feed videos.
   A hit now also requires the video to cover >= half of the window height.
   (Heuristic — verify on a device.)
5. **Detector root safety:** detection now only scans the active window when it
   belongs to the event's package (prevents the partial-id fallback matching
   another app's views).
6. **Launchers / keyboards under MAXLEVEL (default-deny).** `PolicyEngine`
   only whitelisted 5 launchers, so on OPPO/Realme/Vivo/Tecno/Infinix/POCO/
   OnePlus/Motorola the Home screen (and, for unlisted keyboards, typing)
   could be treated as a blocked app. The default HOME app(s) and all enabled
   input methods are now resolved dynamically (60 s cache) and treated as
   system essentials; the static list also gained more OEM launchers.
   `AndroidManifest.xml` `<queries>` gained the HOME and InputMethod intents so
   this works under Android 11+ package visibility.

### Performance
7. `handleContent` ran a `runBlocking` DataStore read + JSON parse on the main
   thread for **every** content-change event of **every** app, and a node-tree
   scan on every event of target apps. It now returns on a cheap package check
   first and throttles scans to one per package per 300 ms.

### Config
8. `INTERNET` and `ACCESS_NETWORK_STATE` declared explicitly in the manifest
   (previously only merged in from the Ads SDK).
9. Versions aligned: `pubspec.yaml` 2.5.1+16, `build.gradle` 2.5.1 / 16,
   `AppConstants.appVersion` 2.5.1 (pubspec previously said 2.2.0+9).
10. `mobile/android/.gitignore` added so `key.properties` / keystores are not
    committed by accident.

## NOT changed — needs you before a Play release
- **AdMob:** both the app id (manifest) and the rewarded unit id
  (`constants.dart`) are Google's *test* ids. Replace with real ones.
- **Signing:** `mobile/android/key.properties` and
  `app/mld-release.keystore` are inside this zip. Keep this zip private.
- **Worker:** production custom-domain `routes` in `wrangler.toml` are still
  commented out, but the app calls `https://api.maxleveldetox.com/api/v1`.
  Deploy + route it (or point `AppConstants.apiBaseUrl` at your workers.dev
  URL). Change the seeded admin password (`ChangeMe_2026!`) on first login.
