# r9.2 (v2.5.2 / versionCode 17) — fixes on top of r9.1 (v2.5.1 / 16)

Driven by a line-by-line comparison against the Social Sentry analysis reports
(`report-enforcement.md`, `report-modes.md`, `report-engagement.md`,
`MASTER-ANALYSIS.md`). Full table: `docs/SOCIAL-SENTRY-PARITY-AUDIT.md`.
r9.1 notes are still in `docs/R9.1-CHANGES.md`.

## Fixed

### Watchdog / persistence
1. **`AccessibilityGuardJobService` was a one-shot job.** It used minimum
   latency + override deadline and nothing re-armed it, so the watchdog ran
   once and then went silent while the process stayed alive — gone exactly
   when an OEM kill needed it. It is now a persisted PERIODIC job (15 min),
   and `schedule()` is idempotent (re-scheduling an id replaces — and can
   cancel — a job that is starting, which `MldApp.onCreate` used to do).
   An incident now really re-schedules the job (`rearm()`), not just flips a
   flag.
2. **Engine 2 could never restart after an OEM kill.** `start()` returned
   early on the persisted `engine2_running` flag, which stays `true` when
   `onDestroy` never ran. Liveness is now a process-local flag
   (`ForegroundAppMonitorService.alive`). `start()` also catches a refused
   background foreground-service start (API 31+) instead of crashing the
   guard job / a11y unbind.
3. **Crash-loop counters only ever grew** (engine 2, lock-my-phone), so six
   ordinary restarts inside the 30-min window blocked further restarts.
   Both now reset after a 60 s clean run (the enforcement service already did).
4. **New `guard/ServiceRevival.kt`** — revives a lock-my-phone / monk
   foreground service whose session is live but whose service is dead. Called
   from every guard pass and from engine 2's 5 s tick. The guard job no longer
   self-disables while such a session is live, and starting a lock-my-phone
   session (re)arms the guard.

### Lock My Phone
5. **No call mode.** The loop called `lockNow()` every 1.5 s regardless, so a
   ringing / in-call screen was re-locked continuously (answering, hanging up
   or dialling an emergency number was impossible). Now, while the telephony
   stack is RINGING / IN_CALL the lock is paused; leaving the call UI for any
   other app re-locks after two ticks. `MODE_IN_COMMUNICATION` is deliberately
   NOT treated as a call (any VoIP app can set it = universal unlock).
   SCREEN_ON / USER_PRESENT re-lock also skips real calls.
6. Duplicate screen receiver registration (sticky restart + MldApp/boot start)
   fixed.

### Anti-uninstall
7. **`UninstallInterceptor` was nearly ineffective.** It only read the event's
   own text (window title — the app name and the Uninstall / Force stop
   buttons are nodes), scanned depth 3, its node budget was never
   decremented, and the root-scan variant was dead code. Now: event text
   first, then a bounded (depth 14 / 220 nodes, throttled) scan of the active
   window; watched-package list extended to the reference app's full OEM list
   plus structural matches; Bangla "deactivate / remove" keywords added; the
   over-broad "app info" keyword removed; honours the permission-recovery
   grace window. Still active ONLY during an enforcing session.

### OEM
8. **OEM autostart / background-power deep links** (Social Sentry E9): Xiaomi,
   OPPO/Realme, Vivo, Huawei/Honor, Samsung, OnePlus, Tecno/Infinix/itel,
   ASUS; falls back to this app's App-info page. New bridge method
   `openOemBackgroundSettings`, button in Permission Center. Component names
   are OEM-internal and every candidate is tried defensively.

### Versions
9. `build.gradle` 2.5.2 / 17, `pubspec.yaml` 2.5.2+17, `AppConstants` 2.5.2.

## Deliberately NOT changed
- **`DnsTamperDetector` stays unwired.** In Social Sentry it protects the
  Private-DNS *filter* feature (`dnsProtectionEnabled` in a Prime profile).
  MAXLEVEL has no DNS-filter feature, so wiring it would only risk
  false-positives on Network settings screens during a Prime commit. Wire it
  (with a stricter match: "private dns" + "hostname") only if DNS filtering is
  ever added.
- Coin-based temporary unlocks (vs. SS minute budgets), no usage-shaming
  stats, no aura decay, no escalating abuse copy — documented product
  decisions.
